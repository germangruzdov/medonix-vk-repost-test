# МедОникс — тест репоста ВК

Версия 0.3.0 переключает `index.html` на новую запись с видео через штатный `VKWebAppShowWallPostBox`. Прежний эксперимент настоящего репоста сохранён на `repost.html`. В мобильной проверке 0.2.3 он получил `client_error / 11 / Access denied` при выданном праве wall; пользователь подтвердил отсутствие репоста на стене. Это подтверждает отказ текущему вызову, но не устанавливает возможность получения отдельного допуска к API у ВК.

Новый сценарий: открыть зарегистрированное приложение, дождаться проверки видео, нажать «Опубликовать видео на моей стене», проверить вложение в штатном окне ВК и подтвердить публикацию. `video.html` содержит тот же интерфейс, что главная страница. Адрес размещения менять не требуется. Счётчик репостов исходной записи не увеличивается.

`video-core.js` проверяет точную исходную запись и совпадение ID медиа с настройкой кампании. Если вложение имеет тип clip, дополнительно требует подтверждения того же объекта от `video.get`; отказ или неожиданный ответ останавливает сценарий до открытия редактора. Это проверка существования объекта; поддержка его прикрепления и воспроизведения ещё требует реального мобильного теста. После ответа редактора повторное чтение `wall.getById` должно подтвердить выбранное видео в созданной записи; без этого успех не показывается и повторная отправка блокируется. Доступ video отдельно не запрашивается: отказ read-only проверки остаётся явным ограничением сценария.

Изменены `app.js`, `core.js`, `video.html`, `index.html`, `privacy.html`, `package.json`; добавлены `video-core.js`, тесты подготовки/проверки публикации и интерфейса. При отмене штатного окна допускается только явная повторная попытка. Сетевая ошибка или неопределённый результат блокируют повторную публикацию в текущем открытии страницы. Между независимыми открытиями приложения общей защиты от дублей нет: перед повторной публикацией нужно проверить стену.

Версия 0.2.3 различает CLIENT, API и AUTH в коротком коде ошибки. Клиентские `error_reason` и `error_description` восстанавливаются только из закрытого словаря технических слов; остальные слова, числа и идентификаторы скрываются. Полный объект ошибки, токены и параметры запросов не выводятся. Импорты изменённых модулей имеют версию для WebView с кешированием.

Мобильная проверка 0.2.2: разрешение wall получено, исходная запись прочитана, ошибка при wall.repost имеет type=client_error, code=11. Это НЕ подтверждённая ошибка API 11 про тестовый режим. Точная причина клиентского отказа ещё не установлена; настройки размещения по одному этому коду менять не следует. Обновление 0.2.3 диагностическое, успешный репост им не подтверждён. После ошибки отправки запрос остаётся заблокированным; автоматической повторной публикации нет.

Версия 0.2.2 исправляет остановку при отсутствии необязательного поля `reposts.user_reposted` в ответе `wall.getById`: в этом случае выполняется дополнительная проверка `likes.isLiked` и используется её поле `copied`. Известный прежний репост по-прежнему не дублируется. При неопределённом ответе обеих проверок или ошибке дополнительного запроса запись не отправляется. Контракт: https://github.com/VKCOM/vk-api-schema/blob/master/likes/responses.json.

Версия 0.2.1 добавляет безопасную диагностику: при ошибке на экране видны этап операции и короткий код, отдельно различаются выдача права wall, чтение исходной записи и проверка прежнего репоста. Необработанные сообщения ВК, токены, параметры запросов и персональные данные в диагностику не включаются. Это диагностическое обновление; оно ещё не устанавливает причину ошибки в реальном ВК.

Статическая тестовая копия VK Mini App. Приложение ВК: **54874242**.

Первоначальная копия подготовлена из локальной версии 0.2.0. Отдельный эксперимент `repost.html` отправляет настоящий репост записи `wall-218885671_6311` только после явного нажатия пользователя. Главная страница с 0.3.0 использует новую запись с видео.

Страница должна запускаться внутри зарегистрированного VK Mini App. В обычном браузере публикация отключена. Право wall в мобильной проверке получено; текущий вызов wall.repost отклонён клиентом. Реальная новая запись с видео по сценарию 0.3.0 ещё не подтверждена.

Пароли и секреты приложения не включены. Временный пользовательский токен выдаёт штатный диалог ВК; токен остаётся в памяти страницы, не логируется, не записывается в хранилище и не отправляется на сервер приложения.

Хостинг предназначен для технического теста. Перед распространением ссылки подписчикам нужно проверить реальную публикацию и воспроизведение на мобильной стене. Доступность из разных сетей и регионов может различаться.

`.nojekyll` отключает обработку файлов Jekyll. Корень ветки main используется как источник GitHub Pages.

Проверка логики: `node --test tests/*.test.mjs` (Node.js 22+). Тесты используют подмену VK Bridge, не выполняют реальные публикации.

SDK VK Bridge 3.0.2 включён в vendor без изменений. Его лицензия находится в `vendor/VK-BRIDGE-LICENSE.txt`.
